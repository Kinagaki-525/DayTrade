# SBI・資金10万円デイトレ 残タスク

このドキュメントでは、現在のデイトレ戦略について
「まだ議論・検証・確認が完了していない事項」を管理する。

未決定事項を推測で埋めないこと。
売買ルールを自動的に変更しないこと。
実運用に入る前に、特にP0項目を確認すること。

## v2で準備済みの技術基盤

以下は未決定事項を確定したものではなく、ユーザー決定後に値や運用を反映できる受け皿のみを準備したもの。

- `config/strategy.yaml` に未決定スクリーニング値を `null` で定義
- 出典付き市場データを `runs/YYYY-MM-DD/` に保存する構成
- 市場データ検証、固定資金条件スクリーニング、価格計算、独立Risk Engine
- `TRADE`、`NO_TRADE`、`REJECTED` を区別するデータ構造
- `trades/recommendations.csv` に推奨履歴を残すためのカラム
- `prompts/nightly_research.md` と `docs/nightly-operation.md` の運用手順
- 日次設定スナップショット、JSON Schema実行時検証、出典台帳と成果物間の整合性検証
- `$prepare-daytrade-plan`と`$record-daytrade-result`による明示起動の運用手順
- 読み取り専用の市場調査・出典監査サブエージェント
- 完全約定・当日決済済み取引に限定した実績Schema、プレビュー、重複防止付きCSV追記

これらの実装を理由に、P0・P1・P2・P3の意思決定済みとは扱わない。

# P0: 実取引開始前に決める必要がある項目

## 1. 翌日の対象銘柄を選ぶルール

現在、最も重要な未決定事項。

資金100,000円で100株購入できる銘柄の中から、
翌日の候補をどのように選ぶか決める。

検討項目：

- 株価上限
- 最低出来高
- 最低売買代金
- 前日騰落率
- 前日の値幅
- 出来高増加率
- スプレッド
- 決算発表予定の除外
- 適時開示・重要材料が出た銘柄の扱い
- ストップ高・ストップ安付近の銘柄の扱い
- 低位株をどこまで許容するか
- 候補が複数ある場合の順位付け: `ranking-v1`として実装済み（`src/ranking.py`）。Event Gate `PASS`候補だけを対象に、実際の売買代金desc・呼値/発動価格の相対比ascの2 FeatureをCompetition RankingしてRank合計で並べる。ただしRank 1を`TRADE`へ変換する最終選定（Selection / Absolute Quality Gate）は未実装のまま。以下は引き続き未決定：
  - 最低売買代金の閾値（Absolute Quality Gateの一部）
  - 呼値/発動価格の相対比の上限閾値（Absolute Quality Gateの一部）
  - Absolute Quality Gate自体の仕様
  - Ranking Rank 1をTRADEへ変換する処理
  - Risk EngineでRank 1がREJECTEDになった場合にRank 2へフォールバックするか
  - 絶対的なNO_TRADE条件（Selectionの一部）
- 条件該当銘柄がない日は取引しないルール

最終的に、
「毎晩、機械的に1銘柄まで絞れる条件」
として定義する。

## 4. 損切りルールの最終決定

現在の仮ルール：

1取引あたり最大損失目安 -500円。

未検証項目：

- -500円固定が適切か
- 100株の場合の-5円固定でよいか
- 株価割合で設定するか

「最大損失500円」ではなく
「損切り発動基準500円」

# 現時点で特に優先する5項目

実際の売買を始める前に、
以下を優先して議論する。

1. 翌日の銘柄選定ルール
2. 利確・損切りルール
3. ギャップアップ時の買い禁止条件
4. 当日中の強制決済方法
5. 取引なし・未約定を含めた記録方式

この5項目が決まるまでは、
現在の戦略を完成版として扱わない。
